# Security model

Trust JWTs only from the configured issuer and audience, using RS256 public keys from the configured JWKS endpoint. The endpoints are deployment configuration, never caller-supplied URLs. Production issuer/JWKS must use HTTPS with standard certificate validation. Local HTTP is confined to the private lab network. The timestamp validator allows Spring Security's default clock skew (60 seconds); keep hosts synchronized and choose token lifetimes accordingly. Require expiration, subject, token ID and scope. Reject missing accounts and permissions. Unknown routes default to deny. Verify scope does not imply administrator scope.

Redis revocations and PostgreSQL account state are authoritative. Failure of either denies service with 503, never a grant. Do not clear revocations or re-enable accounts as an availability workaround. Use durable, authenticated Redis with appropriate persistence/HA and retained revocation TTLs at least through token expiry plus clock skew. This project does not implement a public administrative revocation API; operators/security write revocations through their audited control plane.

The application stores no passwords and issues no production tokens. CSRF is disabled because the API accepts stateless bearer headers, not cookies; enabling cookie authentication requires revisiting CSRF. CORS is not opened. Enforce TLS/HSTS and request/rate limits at the ingress. The lab has no ingress rate limiter and is not safe for public exposure.

Database migrations use an owner role in the lab only. Production should run Flyway with a separate migration identity, grant runtime `SELECT` on principals only, and set `SPRING_FLYWAY_ENABLED=false` on application replicas after migration. Redis should have an ACL identity restricted to EXISTS on the revocation key prefix; the runtime never writes revocations. Use Redis TLS (`SPRING_DATA_REDIS_SSL_ENABLED=true`) and authenticated PostgreSQL TLS with trust roots. No credentials live in Helm values. Feed environment variables through an existing Kubernetes Secret or external secrets integration.

Management endpoints live on 9090, with no app Service exposure. Probes and Prometheus are unauthenticated on that port and must be isolated by network policy/firewall. No other actuator endpoint is exposed. No Kubernetes API access, no host paths, nonroot image, read-only rootfs, seccomp and dropped capabilities. NetworkPolicy requires an enforcing CNI. The example allows public TCP 443 for the IdP; restrict that to your egress gateway or IdP addresses. Namespace labels are trust boundaries controlled by cluster admins.

Trivy checks fixable HIGH/CRITICAL vulnerabilities and secrets. CodeQL runs security-extended analysis. CI includes small security regression assertions and real signed-token negative tests. Scanners cannot prove absence of vulnerabilities; triage findings, pin release image digests, rotate credentials, enable branch protection/review and evaluate supply-chain policy. Floating container/action tags are a documented demonstration limitation; release provenance and SBOM improve evidence but do not make tags immutable.
